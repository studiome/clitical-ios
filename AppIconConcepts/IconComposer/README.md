# Icon Composer layers

Layer sources for building `AppIcon.icon` in Icon Composer
(`/Applications/Xcode.app/Contents/Applications/Icon Composer.app`, v1.6).

All four files are 1024 x 1024, transparent, and contain **fills only** — every
stroke has been converted to an outlined path, because Icon Composer's SVG
import does not carry stroke geometry reliably.

| file | layer | fill |
|---|---|---|
| `1-Background.svg` | background | `#2D6A7B` |
| `2-Limb.svg` | limb | `#FFFFFF` |
| `3-Artery.svg` | artery | `#0E8F8A` |
| `4-Lesions.svg` | lesion markers | `#B32620` |

Stack them bottom to top in that order. `1-Background.svg` can be replaced by
Icon Composer's own background colour — it is included so the canvas matches
`AccentColor.colorset`.

The artery layer already has circular gaps cut where the lesion markers sit, so
the markers need no halo of their own and each layer can move independently.

`2-Limb-NoBleed.svg` is an alternative limb that stops inside the canvas instead
of running off the top edge. Try both: the bleeding version reads as a leg
rather than a sock, but a foreground layer touching the edge may interact badly
with the Liquid Glass edge highlight. Judge it on device.

## Suggested starting point

- limb — no shadow, no specular; it is the ground the other layers sit on
- artery — small neutral shadow, so it floats just above the limb
- lesions — the topmost layer, slightly stronger shadow, specular on

Dark, tinted and clear appearances are generated by Icon Composer from this one
stack. Do not author them by hand.

## Still required

The app deploys to **iOS 16.0**, so `AppIcon.icon` does not replace
`clitical/Assets.xcassets/AppIcon.appiconset/` — the flattened PNGs there are
still what every release before iOS 26 uses. Keep both in sync.

## Regenerating

`build-layers.py` derives these files from the centrelines in
`../vector/AppIcon-Light.svg`. It expects `leg-path.txt` and `bodymask.png` from
the authoring scratch directory, so treat it as a record of how the outlines
were produced rather than a one-command build.
